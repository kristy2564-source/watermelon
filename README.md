# 合成大西瓜（穆夏风格 · 2.7）

一个清新草绿配色、穆夏（Alphonse Mucha）装饰风格的「合成大西瓜」小游戏。纯前端单文件实现，手机 / 桌面浏览器打开即玩。

**2.0 新增**：道具系统（合成解锁）+ 排行榜双模式（全服榜 / 道具挑战榜）。

**2.1 新增**：
- **游戏模式选择**：开场弹窗可切换 🍉 经典（纯净局，等价 1.0）/ ✨ 道具（开启道具栏）两种玩法
- **合成去飘字**：合成时不再弹"+分"飘字，画面更统一；道具获得飘字保留（技术信号不可丢）
- **边框裁切**：道具模式下自动裁掉装饰框底部 25%，避免藤蔓压住道具栏

**2.2 新增**：
- **道具效果随机化**：摘除/同类消不再是「指定目标」，而是「随机生效」—— 摘除 = 随机移除 1 个水果（每个机会均等），同类消 = 随机锁定场上某一类并全部消除，洗牌保持随机重排；完全不可指定，操作更刺激
- **使用前确认弹窗**：每次点道具都会弹窗说明「这个效果具体是怎么随机的、不能指定什么」，避免误触后悔；点空白 / 「再想想」可取消，「确认使用」才生效
- **边框柔和镂空**：道具模式用径向渐变 mask 让装饰框底部自然淡出（替代之前的硬裁切），两侧藤蔓保留并向下包裹，视觉更优雅

**2.3 新增**：
- **三秒预告期**：使用道具后等待 3 秒再开始生效。被锁定的目标描出柔和呼吸光晕、顶部居中胶囊显示「道具名 + 剩余秒数 + 进度条」，暂停/结束/关弹窗时倒计时自动冻结
- **慢放动画**：消散中水果 `dying` 0→1 缩放淡出 ≈0.77s（脱离物理），飘字扩散/淡出放慢到 ~1.28s，洗牌改「逐批下落」（每批 2 个）让过程更舒展
- **每局 6 次上限**：新增「✨ 本局道具 X/6 · 还剩 N 次」实时计数；用尽即三道具槽全部置灰、计数文本变红；次数随快照持久化（刷新不能绕过）

**2.4 调整**：
- **锁定动效改「柔光轻浮」**：去掉 2.3 的虚线圆环 + 收缩环，改为柔和径向光晕 + 目标微微上浮（无任何硬边圆）；暖白腰色让同色目标也能看清，光晕随倒计时由外扩转收拢、由淡转浓

**2.5 调整**：
- **「重新开始」回到主界面**：顶部按钮改为收起当前局、回到开场模式选择页（沿用上次所选模式，可一键切换），不再"原地同模式直开一局"
- **结束页双出口**：原本只有一个"再来一局"，现在并列「再来一局」（同模式速开）+「换个模式」（回主界面）；快速续玩与切模式都顺手

**2.6 调整**（手机端适配）：
- **开场页加滚动条**：手机端引导文案较长时，`.start-overlay` 可纵向滚动（穆夏绿细圆滚动条），内容不足时卡片居中、超出时可滚到底看到「开始挑战」按钮
- **窄屏布局控制**：@media (max-width:680px) 下收紧开场页 padding、装饰图 86→64px、标题 28→24px、引导文案 13→12.5px

**2.7 调整**（道具难度提升 · 标准档）：
- **解锁门槛提高**：橘子 → **柠檬**（🍃摘除）、桃子 → **菠萝**（🔮同类消）、菠萝 → **哈密瓜**（🌪洗牌）；三个道具的解锁梯度从 3/6/7 拉到 4/7/8，橘子不再白给道具
- **库存上限 2 → 1**：每种道具最多存 1 个，不能囤积，拿到就得权衡何时用
- **本局上限 6 → 4 次**：预算条显示「✨ 本局道具 X/4 · 还剩 N 次」
- **满仓反馈**：库存已满时合成仍会飘灰色「XX 已满」提示，避免玩家以为合成没触发
- 未采用「概率获得」：道具**效果**随机是玩法趣味，但**获得**随机是挫败感 —— 同样的操作有时给有时不给会让玩家觉得被惩罚

**2.3 新增**（应玩家反馈「消除太快 / 看不清」）：
- **三秒预告**：确认使用后 **3 秒** 才真正生效 —— 期间被锁定的目标水果会带 **脉动光环 + 收缩环**（清晰可见），顶部胶囊显示道具名 + 剩余秒数 + 进度条。暂停/游戏结束自动冻结倒计时，无浪费
- **慢放动画**：消除时目标水果以 **~0.77 秒** 缩放淡出（不再瞬间消失），飘字也更慢；洗牌改为**逐批下落**（每批 2 个，间隔更大），撒落过程更舒展
- **每局上限 4 次**：道具栏上方新增「✨ 本局道具 X/4 · 还剩 N 次」实时计数，用尽即所有道具槽置灰；次数随快照持久化，**刷新不能绕过上限**（2.7 由 6 次下调为 4 次）

## 玩法（2.1）

基础规则同 1.0：
- 移动鼠标 / 手指瞄准落点，点击放下水果
- 相同的两个水果相撞会合成更大的水果
- 一路合成到大西瓜即可封顶得分
- 水果堆过顶部危险线即结束
- 连续点击有 380ms 投放冷却，防止连点连发

**2.1 新增模式选择**（开场弹窗 segmented control，二选一）：

| 模式 | 玩法 | 排行榜归类 |
| --- | --- | --- |
| 🍉 **经典** | 纯净局，等价 1.0：无道具栏、合成不获得道具 | 永远进「全服榜」 |
| ✨ **道具** | 显示道具栏（合成解锁 3 道具），可用 | 用过道具→「道具挑战榜」，否则→「全服榜」 |

模式选择同步影响：① 引导文案是否有道具介绍；② 开始按钮文案（经典 =「🍉 开始游戏」/ 道具 =「✨ 开始挑战」）；③ 是否裁切装饰框底部；④ 开排行榜时的默认 tab；⑤ 本局缓存中 gameMode 字段（恢复时同步刷新 UI 状态）。

**2.0 道具系统**（道具模式 · 合成对应水果解锁，库存上限 1、本局清零）：

| 合成目标 | 解锁道具 | 图标 | 效果（2.2 随机化） |
| --- | --- | --- | --- |
| **柠檬**（2.7 起，原橘子） | **摘除** | 🍃 | 随机移除场上 1 个水果（每个机会均等，大果也可能被摘） |
| **椰子**（2.9 起换素材，原菠萝） | **同类消** | 🔮 | 随机锁定场上某一类，该类型全部一起消除 |

## 排行榜（2.0 双模式）

游戏内置排行榜，「云端优先 + 自动降级」+ 2.0 新增**双模式榜**：

- **全服榜（纯净局）**：本局未使用任何道具时计入
- **道具挑战榜**：本局使用过任一道具时计入（lbMode=power）
- 切换 tab 即可在两榜之间查询（云端 + 本机纪录均按 mode 分两套 key）
- 云端请求超时时间为 10 秒，失败时榜单底部会显示具体原因，便于排查

### 接入自己的 Supabase（2.0）

编辑 `合成大西瓜.html` 里的两行常量：

```js
const LB_BASE = "https://你的项目.supabase.co/rest/v1";
const LB_KEY  = "你的 anon / publishable key";
```

然后在 Supabase 的 SQL Editor 跑 **`SUPABASE_MIGRATION_2.0.sql`**（一键建表 + 加 mode 列 + 唯一索引）：

```sql
-- 全新建表
create table if not exists score(
  id bigint generated by default as identity primary key,
  name text not null,
  score int not null default 0 check (score between 0 and 999999),
  mode text not null default 'classic',    -- classic=全服榜(纯净) / power=道具挑战榜
  created_at timestamptz default now());
alter table score enable row level security;
create policy "anon_ins" on score for insert to anon with check (true);
create policy "anon_sel" on score for select to anon using (true);
grant usage on schema public to anon;
grant select, insert on table score to anon;

-- 1.0 老表升级到 2.0（幂等，可重复执行）
alter table score add column if not exists mode text not null default 'classic';
alter table score drop constraint if exists score_name_key;
create unique index if not exists score_name_mode_key on score(name, mode);
```

> 注意：`LB_KEY` 只能填 anon / publishable 这类**公开**密钥，切勿填 `service_role`。
